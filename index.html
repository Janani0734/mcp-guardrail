Nothing risky runs until someone says yes

  1. The agent calls a risky tool

    Your agent talks to MCP-Guardrail over the Model Context Protocol, the same way it talks to any other tool server.

  2. The policy engine checks the rules

    Rules you set can block a target outright, or hold it for approval with its own time limit. If the rules can’t be read, nothing goes through.

  3. A person approves or rejects

    The request waits in the dashboard and expires on its own. Every request and decision is added to a hash-chained audit log.

What works today

Each of these has been tested end to end against the live service.

Approval requests that expire
Pending, approved, rejected and expired states, with a five-minute default window.
Rules per tool and target
Deny a target, or require approval with a custom window, managed through an admin API.
Protected records
The server refuses to stage deletion of protected tasks, whatever the AI client decides.
Tamper-evident audit trail
Each event is hashed with the one before it, and the latest hash is checkpointed to Cloudflare R2.
Works with Claude
Connect Claude Desktop to the MCP endpoint as a custom connector.
